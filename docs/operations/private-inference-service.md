# Private Python inference service

## Scope and trust boundary

Phase 2B implements an internal ASGI service around the frozen project-owned
Detection and Recognition pipeline. It is not a browser API and has not been
publicly deployed. The implemented Next.js BFF is the only intended caller.
Coolify must place the service on an internal application network, must not
publish its port, and must expose only the BFF through the public proxy when
deployment is approved.

The process contains exactly one model pair and one single-thread inference
executor. It has no CORS middleware, cookies, public API keys, multipart parser,
database, queue broker, object store, background inference, or application log
files.

## Endpoints and authentication

- `GET /healthz` reports process liveness only.
- `GET /readyz` reports ready only after configuration, bundle identities,
  model loading, and pipeline initialization succeed and the sole inference
  slot is available.
- `POST /api/v1/inference` accepts one raw `image/jpeg` or `image/png` body.

The POST contract is
`schemas/internal/v1/anpr-private-inference-v1.openapi.yaml`. Required headers
are `Authorization: Bearer <internal credential>`, `X-ANPR-Request-ID`,
`X-ANPR-Admission-ID`, `X-ANPR-Locale`, and
`X-ANPR-Privacy-Acknowledged: true`. Request and admission IDs are generated by
the BFF, not by the browser. Production mode without a configured
credential fails readiness. Credentials use a constant-time comparison and are
never logged.

## Model verification and execution

`ANPR_PRIVATE_MODEL_BUNDLE` identifies an owner-controlled, read-only bundle
outside Git. Startup verifies its private classification manifest and the exact
approved SHA-256 identities before loading one Detection and one Recognition
model. Phase 2B is fixed to CPU. A missing file, hash mismatch, incompatible
configuration, load error, or component failure leaves the service non-ready.

The governed order is raw-image validation, Project Detection, deterministic
top-1 selection by descending confidence then box coordinates,
`BLUE_BAND_GLYPH_QUAD_V1`, Project Recognition, and existing structural
validation. Multiple detections are explicitly reported; multi-plate support is
not implied. The response identifies `prediction_source` as the existing project
decoder and reports whether decoding changed the raw sequence; no transformation
is silent. Confidence fields are informational, not calibrated certainty.
When the existing decoder produces no supported candidate, the result is
`recognition_unresolved` with a null prediction; it is never labeled as a
prediction.

## Validation, admission, and deadlines

The service reads the raw ASGI stream and never uses a multipart or spooling
abstraction. It rejects unsupported media types before decoding, declared or
streamed bodies over 10 MiB, signature mismatches, malformed or truncated
images, multiple frames, dimensions over 8,192, more than 20 million pixels,
and decompression bombs. Decoding normalizes EXIF orientation into a new pixel
array; source metadata is not carried into the pipeline or response.

There is one global active inference and queue depth zero. A second request is
rejected immediately with `CAPACITY_UNAVAILABLE`; there is no automatic retry.
The service rejects a repeated generated request ID within its last 256 admitted
requests with `409 INVALID_REQUEST`. This in-memory replay guard stores IDs only,
not images or results; it resets on process restart. The BFF must also
avoid resubmitting the same request.
Blocking validation/decoding and model work share one single-worker executor.
The deadline includes upload reading, validation, decoding, and inference. If
client cancellation or the deadline occurs while worker work is running, the
slot remains occupied until that work actually finishes. The deadline is
provisional and must be replaced by staging benchmarks on the actual Coolify
host.

## Retention and logging

The production call passes `output_directory=None`, so the integration creates
no annotated image, crop, artifact, upload file, or temporary file. Request
bytes and decoded arrays remain in memory and references are released on every
request exit. The service provides no history or persistence.

Operational events are allowlisted JSON on stdout/stderr. They may contain a
generated request ID, safe status/error category, bounded timings,
application/API/schema versions, safe model versions, and readiness/capacity
state. They cannot contain image data, filenames, plate text, predictions,
crops, boxes, image hashes, credentials, admission IDs, exception text, private
paths, or request metadata. Uvicorn access logging is disabled.

## Configuration and local validation

- `ANPR_PRIVATE_MODEL_BUNDLE`: private bundle location; never publish its value.
- `ANPR_SERVICE_ENV`: `development`, `test`, or `production`.
- `ANPR_INTERNAL_SERVICE_CREDENTIAL`: injected secret of at least 32 characters;
  mandatory in production and prohibited from logs/repository content.
- `ANPR_INFERENCE_DEVICE`: must be `cpu` in Phase 2B.
- `ANPR_INFERENCE_DEADLINE_SECONDS`: provisional 1–120 second value.
- `ANPR_APPLICATION_VERSION`: safe release identifier.
- `ANPR_SERVICE_HOST`: loopback by default; a container still requires a private network.
- `ANPR_SERVICE_PORT`: internal listener port, default 8080.

Local launch uses `python scripts/launch_private_inference_service.py`. Tests use
`uv run pytest`. Do not proxy or tunnel the local listener.

Starlette supplies the minimal ASGI routing/request layer and Uvicorn the
single-worker server. Only base packages are used: no standard extras,
multipart package, templates, database integration, or documentation UI. Both
declare BSD-3-Clause. Their small transitive set remains subject to the
repository-wide licensing audit; this record is not legal approval.

Local CPU containers and a bounded, loopback-only Coolify staging check have
been completed; the staging service was stopped. No public route, DNS change,
public deployment, GPU mode, or production-capacity qualification exists.
Reverse-proxy behavior, broader security and license review, final capacity
settings, and explicit owner approval remain open.
